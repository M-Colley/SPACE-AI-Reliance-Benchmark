2. Resolve upstream reconciliation and model snapshot/settings. Freeze parsing and failure rules. Share model ID, prompt policy and settings with Mark before full benchmarking.
3. Commit and publish code/config before live requests. 4. Commit/publish the corrected full-run version before formal execution. Run every source record once. Match outputs by item ID, not completion order. Preserve errors and raw responses. Resolve any technical failures with a separately specified recovery policy, not silent replacement or full-pool reruns.
5. Report full-pool category accuracy and missing/invalid/error counts. Report record-level versus grouped-item definitions explicitly.
6. Preselect pilot candidates stratified by category and first-run correctness. Candidate number, strata quotas, family grouping and random seed remain TO BE AGREED before selection. Do not claim these rules are already preregistered. Save and commit a JSON list of candidate IDs before repeated runs.
7. Repeat those same candidates four times with identical scientific settings. Use phase repeat, repeat-number 2/3/4/5 and separate run IDs. The script requires --candidate-ids. The full-001 response remains the first formal answer; technical tests never count towards the five.
8. Suggested stability rule FOR REVIEW: first-run correctness must agree with at least 4 of all 5 formal runs. Also report exact-option agreement. Invalid/missing responses must be resolved in the rule, not counted as ordinary incorrect responses automatically. No stability-selection program is implemented yet. Agree this rule before repeats and human piloting; if candidate replacement is permitted, define it in advance.
9. Human pilot follows ethics approval and frozen candidate preparation. Use its difficulty estimates for curated-library selection. Report how the library differs from full-pool performance. Human selection, learning/retention assignment and power simulation are separate next-stage work.

Publication: public source and config before formal run, with commit URL saved. Never rewrite prior commits to hide changes. Public repository is a method record, not a substitute for later formal preregistration. Raw responses and exact request archives are saved locally; review stimulus permissions and contents before any public release. No API credentials are logged in request archives.
